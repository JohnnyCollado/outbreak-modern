## 1. What it is

A small server inside our app. When a player presses **Host game**, it starts on that device and the game on every
device in the room (the host's own included) talks to it. It answers the three things the game expects from the old
KDDI service, on the local network only:

| Part | Port (Windows host / Android host) | Job |
|---|---|---|
| Login pages | HTTPS 443 / 18443 | quick login: hand the game a session id, then the lobby address |
| Lobby | TCP 8300 | handles, areas, rooms, game slots, create/join/start, hand-off to the relay |
| Relay | TCP 8690 | copy each player's in-game messages to the other players of the same game |
| Hello + discovery | UDP 18300 (broadcast) and TCP 18300 | announce the game on the network (P6); the pre-launch check and the device's identity for quick login (P12, P13) |

Android can't open ports below 1024, so an Android host uses 18443 for login and our clients' network adapter sends
the game's port-443 connections there (plan P8). Players never see any of this.

## 2. How it fits

```
 Host device                                              Other devices
 ┌───────────────────────────────┐                        ┌──────────────────────────┐
 │ game (recompiled)             │                        │ game (recompiled)        │
 │   └ network adapter (DEV9) ───┼── host sockets ──┐     │   └ network adapter ─────┼─┐
 │ ob_server (own thread)  ◄─────┼──────────────────┴─────┼──────────────────────────┼─┘ LAN
 │   login · lobby · relay       │                        │                          │
 └───────────────────────────────┘                        └──────────────────────────┘
```

- Each client's adapter answers the game's DNS: `www01.kddi-mmbb.jp` (and `gate1…`, unused) → the host's LAN
  address (on the host itself, its own address).
- DNAS is skipped in our client (plan P4 result); a hook found in S3.
- Lobby and relay are the same code on Windows and Android (C++, sockets, one thread with `poll`/`select`). Nothing
  runs on the game thread (P9); the server costs nothing when not hosting.

| Path | What | Licence |
|---|---|---|
| `native/ob_server/` | the server library: `web` (HTTPS pages via mbedTLS 2.28), `lobby`, `relay`, `discovery`, `state` (accounts, handles, rooms in memory; accounts + handles saved to `online/accounts.json` in the settings folder) | **AGPL-3.0**, own `LICENSE` and credit to Bioserver1/obsrv.org (its protocol knowledge) |

certificate is generated once per install (self-signed is enough for the login pages: Bioserver1's README; the
game's browser checking it is [?], tested in S3).

   answering "no file"; if the game refuses, work out its format from the game's code; only as a last resort include
   the fan server's copy (allowed under AGPL with credit, since `ob_server` is AGPL anyway).
2. **Lobby names:** the fan server uses "East Town"/"West Town" and rooms R1-RA in English. Keep those, or use names
   of our own (Japanese or English)? They're only labels.
3. **Dedicated `ob_server.exe`:** still wanted in the first release (N6 default)? It's cheap, since it's the same
   library.
