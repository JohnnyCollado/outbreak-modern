# Milestone 3: 2D

## Goal

From the design: "GS packet interpreter: boot image, logos, title screen; pad input." Texture
replacement starts here too (design Decision 6, "Order").

## Done when

- The boot image, the logos and the title screen draw on both platforms. A frame compared with a
  PCSX2 frame of the same moment shows no visible difference (a "golden-frame test", with a
  threshold to be chosen).
- A controller drives the menus on both platforms.
- The text renderer draws Shift-JIS text (decomp `font.c`).

## Depends on M0, M2

The title screen lives in the DEMO overlay (`demo/title.c`, `func_00548EB0`; port map). So
"title screen" needs **one overlay** loaded, which the design puts in M4. Either M3 loads DEMO
early, or M3's check stops at the logos. The design doesn't say which; **to decide**.

## Work

1. **Take the packets the game builds.** No real DMA: when the game kicks VIF1/GIF, hand its
   finished packet lists to the renderer (port map, Rendering: `dmaq.c`, `drawlist.c`). The game
   also waits for DMA-end interrupts and GS FINISH (`dmaq.c`); these must be raised in the order
   the game expects.
2. **GS interpreter on Vulkan, 2D first.** GIF tags (PACKED/REGLIST/IMAGE), A+D register writes,
   sprites, triangles, alpha blending, Z test, and texture upload from GS memory.
   - GS memory (4 MiB) holds frame buffers, Z and textures in **swizzled** layouts per format.
     A reference interpreter needs PCSX2-style layouts to show what the game uploaded. PCSX2's
     `GSLocalMemory` is the reference (GPL-3.0).
   - The "native renderers per draw type" step (decomp ROADMAP Phase 5) comes later, not in M3.
3. **Display.** `GS_PMODE/DISPFB/DISPLAY` decide which buffer is shown and how (display.c). The
   flip comes on v-blank: tie it to the swapchain present.
4. **Pad.** Fill PadData at 0x292D40 the way `padread.c` `func_001A5C20` expects (port map, Input),
   from SDL3 game controllers. Answer the `scePad2*` and `sceDbc*` calls.
5. **Texture replacement, first cut.** Compute PCSX2's key (`TEX0Hash`, `CLUTHash`, format and
   size, as in `GSTextureReplacements.cpp` `TextureName`) for each texture the GS interpreter sees,
   and look up a PNG replacement. With an interpreter the key can be computed **the same way
   PCSX2 does**: from GS memory, at draw time. Computing it earlier, from the TIM2 at load time
   (the design's plan), is harder (README, corrections). Leave that for later.
6. **Golden frames.** Capture PCSX2 frames of the same moments as reference. REO does the same
   ("PCSX2 is used as a black box to compare against").

## What's needed

- PCSX2 or ARMSX2 for reference frames, and your disc in it. Capturing on the Odin through ARMSX2
  needs your "proceed".
- A controller on each platform.
- The REOB HD pack (NoBigDeal La, kept out of git) to test texture keys. Whether its file names
  use the key format of the current PCSX2 (`TEXTURE_FILENAME_*_FORMAT_STRING`) or an older one
  (PCSX2 still parses "OLD_REGION" names) is **unknown**: list its file names.

## Limitations

- **A GS interpreter is the slow path.** It is for correctness and debugging, not the final
  renderer. Upscaling and the 4K pack's memory plan (Decision 6) don't belong on it.
- **PCSX2-compatible keys tie us to PCSX2's GS memory layout and hashing.** If PCSX2 changes its
  hash, packs made for the new PCSX2 stop matching, and the other way round.
- **GPL-3.0**: reimplementing PCSX2's layouts and hashes from its source brings GPL obligations.
  This repository has no licence yet (README).

## Unknowns

- **The exact GS features the 2D path uses** (which formats, blend modes, CLUT modes CSM1/CSM2).
  Known only by logging what the game sends.
- **Whether the boot image and logos are uploaded in a way that hits any GS corner** that
  PCSX2-style emulation needs a hack for. No evidence either way.
- **Whether the HD pack's keys match textures as the native port sees them.** They should, if the
  port feeds GS memory the same bytes, but it's unproven until a texture is matched.
- **Touch controls on Android.** Not in the design. Whether you want them is **unknown** (the
  Odin has physical controls).
