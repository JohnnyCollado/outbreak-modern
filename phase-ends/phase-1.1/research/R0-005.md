## Findings
(1) PCSX2 Qt behaviour (wiki/forum content is search-snippet only, mostly old)
- Screenshot keys: PCSX2 wiki snippet lists Shift+F8 (screenshot) and Ctrl+Shift+F8 (multi-frame GS dump); a fan wiki says plain F8. Conflict; confirm in-app. Snippet says screenshot is taken at the current rendering (internal) resolution, saved to the snaps folder.
- Hardware renderer: internal resolution is a multiplier (iTechGuides 2026 cites FAQ: 3x ~1080p, 6x ~4K; not exact for all games). Software renderer: CPU-rendered, native internal resolution only, CPU-heavy (wiki snippet, old).
- Deinterlace (2012 forum and older wiki, unverified for 2.9): Bob = closest to PS2 field offset but shimmers; Weave leaves combing; Blend blurs; Adaptive = motion-adaptive. Sources disagree on grouping.
- No sourced info on stretch/aspect or bilinear/display filtering. No CLI or hotkey screenshot trigger documented; automating needs key injection or gsrunner.
(2) Other projects
- PCSX2 GS dump: a dump records EE-to-GS transfers plus initial GS state. Wiki (snippet) says pixel-level checks per draw call: slight difference = rounding bug, large = real bug. Limit: replay cannot reproduce bugs in initial GS memory and does not answer EE memory reads.
- Dolphin FifoCI: 2013 dev post (search snippet): generates PNGs per revision from FIFO logs and compares to real GameCube output. Current pipeline and thresholds not verified.
- SSIM examples found were generic (twenty-twenty crate; a Python golden-screenshot framework using 0.98). Not emulator standards. Secondhand claim: PSNR/MSE correlate poorly with perception.
(3) Legitimate-difference sources: no sourced material retrieved. Dithering, RGB5A1 expansion, PMODE merge and field offset are named by the brief but unverified here; check the PCSX2 GS source or the GS manual before relying on them.

## Recommendation (my reasoning, not sourced)
- Control the reference: same PCSX2 build, SW renderer at 1x, fixed deinterlace, aspect and filtering; same frame index counted from boot; same crop region. Record all settings in the gate.
- Measure the noise floor first: boot PCSX2 twice and diff its own frames. If identical, the gate can be exact on those frames.
- Metric: report max per-channel delta and percent of pixels with delta > 0, per frame. Gate on both.
- Justify N from a legitimate cause, not from failures: a 5-bit channel expanded to 8-bit steps by 255/31, about 8.2 levels, so a rounding-mode mismatch on RGB5 input gives max delta about 8. Allow a bound of that size only on pixels the GS model marks as RGB5-sourced; elsewhere require 0. Verify the bound against the PCSX2 source.
- Freeze thresholds before running the gate and log every failure. Do not raise N after a failure.
- Avoid one global hash across machines; compare per frame.
