### 2. Privileged registers, CSR, IRQs (pcsx2/GS.cpp is core, outside GS/)
- `alignas(16) u8 g_RealGSMem[Ps2MemSize::GSregs];` is the 8 KB PS2 GS register block. `FreezeMem(PS2MEM_GS, 0x2000)` in `SaveStateBase::gsFreeze()`. MTGS ring keeps its own `RingBuffer.Regs` copy, which is what gets passed as `basemem` to GSopen.
- CSR writes are handled in core: `static __fi void gsCSRwrite(const tGS_CSR& csr)`. RESET: clears signal/finish state, memsets g_RealGSMem, calls `MTGS::ResetGS(false)`. SIGNAL: updates GSSIGLBLID.SIGID, calls `gsIrq()` unless GSIMR.SIGMSK; resumes paused GIF via `gifUnit.Execute`. FINISH/HSINT/VSINT/EDWINT clear their CSR bits.
- Dispatchers: `gsWrite8/16/32`, `gsWrite64_page_00/01`, `gsWrite128_page_01` route GS_CSR / GS_IMR / GS_BUSDIR. `IMRwrite` stores `(value & 0x1f00)|0x6000` into GSIMR and raises `gsIrq()` if unmasked pending.
- `void gsIrq()` = `hwIntcIrq(INTC_GS)`. This is the only IRQ path to core; a standalone embed must supply its own equivalent (or include this file).
- `gsSetVideoMode(GS_VideoMode)`, `gsReset()` (calls `MTGS::ResetGS(true)`, zeroes g_RealGSMem, `UpdateVSyncRate(true)`), `gsPostVsyncStart()` (reads/clears `s_GSRegistersWritten`, calls `MTGS::PostVsyncStart(registers_written)`).
- Note: the summarizer did not show `GSvsync`/`GSreset` call sites in core by name; the MTGS dispatch shows the actual calls.

### 3. Threading (pcsx2/MTGS.cpp)
- GS runs on its own thread: `MTGS::StartThread()` -> `s_thread.Start(&MTGS::ThreadEntryPoint)`. `ThreadEntryPoint` calls `GSopen(EmuConfig.GS, EmuConfig.GS.Renderer, RingBuffer.Regs, ...)`, then `MainLoop()`, then `GSclose()`.
- Ring: `BufferedData` with `u128 m_Ring[RingBufferSize]` (size not extracted), `s_WritePos` (EE), `s_ReadPos` (GS), atomics.

- Direct single-thread use: possible for the GS.cpp free functions, since they only forward to globals. The MTGS ring is not required. Plan should treat GS as single-thread-affine for device calls.

### 8. Build (pcsx2/CMakeLists.txt at tag)
- No separate GS library target. GS sources are in `pcsx2GSSources` / `pcsx2GSSourcesUnshared` / `pcsx2GSHeaders`, compiled into the `PCSX2` executable or `PCSX2_LTO`. Multi-ISA SIMD builds make `GS-{sse4,avx,avx2}` STATIC libs (`add_library(GS-${isa} STATIC ...)`), linked WHOLE_ARCHIVE into PCSX2.
- Links: `common`, `Zstd::Zstd` via PCSX2_FLAGS. OGL: `glad` (+ opengl32 on Windows). Vulkan: vulkan-headers + shaderc include dir. DX (Windows): `d3d11.lib d3d12.lib dxgi.lib dxcompiler.lib`, D3D12MemAlloc.
- Consequence: embedding the GS requires `pcsx2/` headers (Config.h, Host.h, GS/GS.h), `common/`, and the core files GS.cpp, MTGS.cpp (or stubs for them), plus their Ps2 memory/gif dependencies. Dependency list beyond this was not traced.
