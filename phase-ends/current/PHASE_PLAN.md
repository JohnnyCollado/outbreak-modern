## Rationale
- Shortest path, no spike: T7 builds the real library; its smoke exe is the first consumer and stays as the library's test.
- SW before Vulkan, inside T8 not as a task: the refs are PCSX2 SW at 1x, so PCSX2-SW in our runner against them isolates adapter faults (packet order, privileged-register mirroring, field parity, snapshot crop) from HW-vs-SW renderer differences, at no build cost (SW is in the same library). Expected close to green; what remains is our EE/VU1/game data, which no GS fixes (those become 1.4/1.5's scope).
- Cut at the GS frontend, not at `GSRasterBackend`: that interface is shaped by our own draw decode (Submit, LoadClut; research/2026-10-22-gs-seam-in-ps2recomp.md), while PCSX2 wants the raw GIF stream and privileged writes. So: raw-GIF tee at the arbiter sink (path id kept), a privileged-write tee, GSvsync at VBlankStart, readback and snapshot through PCSX2; our frontend keeps decoding for CSR (SIGNAL/FINISH) and transfer state, its raster backend draws nothing. Interrupts stay on our side, as gt4 does (R1.3-007), so the EE/INTC path is untouched.
- Vulkan before D3D11: Android is Vulkan-only, so Windows exercises the renderer Android will use; D3D11 is the decided fallback only if Vulkan blocks.
- T9 is `review: yes`: the gate reads snapshots, so only the developer's eyes confirm the picture reaches the window.
- Frame time is an observation (T10), not a speed goal; a small env-gated patch because it will be re-measured (Android, later phases).
- No `effort: high`: every done-when is arbitrated by a build, a test or the gate.

## Risks
- PCSX2's GS may lean on more of the core than the stub list (R1.3-008/009 lists come from summarizing fetches): T7 grows. Fallback, as gt4 did: build the PCSX2 core library without its JIT and call the same GS API; a bigger binary, same adapter.
- Two imgui versions (PS2Recomp v1.92.7-docking, PCSX2 3rdparty) in one link: duplicate or mismatched symbols. T7 settles it before T8 links the runner.
- shaderc: a heavy build and a runtime DLL; a missing DLL or shader tree fails only at GSopen(VK). T7's smoke (b) catches it.
- Vulkan on raylib's window (WGL context on the same HWND) or on a hidden window may fail or skip presents (T9).
- Field parity: PCSX2 derives the field from CSR FIELD inverted; a wrong parity shifts by one line and raises the shares (T8 checks it on pcsx2-sw first).
- Readback through the wrong PCSX2 call leaves garbage in game RAM where the game reads back VRAM (sceGsExecStoreImage).
- PCSX2-HW (Vulkan) at 1x is not bit-equal to the PCSX2-SW refs: this milestone asks only for baseline-1.2 or better, but the generation's done-criteria (static screens green) may need, in 1.6, gating with `pcsx2-sw` or a developer-approved plan change; T10's numbers show the size of it.
- What stays wrong under PCSX2's GS is our EE/VU1/game data (for example CAPCOM's offset, if it is in the game's registers): visible here, fixed in 1.4/1.5.
- Old T1 may be in flight at the stop: its patch, if committed, shifts patch numbers and the CPU numbers T8 compares against.
- The stale gate gets longer with the PCSX2 library in the stamp; the low-memory guard can kill a background run in its report phase: re-run in the foreground on the fresh stamp.
