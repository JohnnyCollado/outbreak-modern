## Rationale
- Order: capture kit (T1) and gate tool (T2) and our-side measurements (T3) run before the developer's sitting (T4), so the sitting needs no waiting and the intake check catches wrong settings or wrong dimensions while PCSX2 is still open. Tolerance (T5) needs both noise floors. Self-tests run before the freeze (T6) so a d/p that cannot catch a shifted glyph is never frozen. Baseline (T7) only after the freeze.
- Reference settings: Software renderer, Screenshot Resolution = Internal Resolution (Aspect Uncorrected), PNG, deinterlace Off (pass-through, R1.2-006), bilinear present Off, crop 0, no FXAA/ShadeBoost/TV shader/CAS. Off rather than a Weave/Bob mode: Off is the documented no-op path; Bob adds a half-line offset (R1.2-006). If T1's probe shows the game in field mode, T5 analyses field merge against these references; the reference stays the least-processed PCSX2 output.
- No resampling ever: a PCSX2 image that is not 512x448 is a stop (`question` with evidence), not a resize; resizing invents deltas the tolerance would then have to absorb.
- Capture window: alignment is by best frame in a window (generation plan line 10); title "PRESS START" blinks and menus may animate, so T3 measures the change period per screen and sets the window length in `gate/boot.script` to cover it; the manifest records it.
- Best-frame tie-break (determinism): lowest share, then lowest max delta, then lowest k.
- `effort: high` on T5 only: d and p are a judgment from evidence that no test arbitrates. T6 is `review: yes` because the frozen tolerance defines "green" for the rest of the generation; the developer sees the justification and self-test results before the freeze commit. T4 is `review: yes`: the developer's hands-on sitting.
- Gate exit codes are the gate's own (runner codes 2/3/4 are reported, not passed through): 0 all green, 1 some screen red, 2 setup error (refs missing, sha256 mismatch, size mismatch, tolerance file missing), 3 boot failed, 4 recompile failed, 5 self-test failed.

## Risks
- PCSX2's Software output may not be 512x448 (width = FBW*64, R1.2-006; the boot buffer is 640 wide, R1.2-005). T1 predicts it, T4 measures it before the sitting continues; a mismatch stops the phase for a decision, never a resample.

- The game may run in field mode, making our line-duplicated presentation differ from PCSX2's on every other line; then field merge is analysed in T5 (legitimate presentation choice or a real fault for 1.3+), with the evidence written down.
- PCSX2 ref a vs ref b may differ more than a shifted glyph does, leaving no valid p: T5 returns `question`; the metric form is in the generation plan, so a change goes to the developer.
- GS privileged registers may not be readable through `watch` without a runtime patch: T1 records "unknown" and the deinterlace choice rests on the PCSX2 source reading (Off = pass-through).
- Gate wall time is unknown (visible boot reached char select at 1:39; recompile ~340 s): a stale gate run may exceed one tool call; it runs through run.sh with a raised timeout, a background shell if longer (house rules §9).
- PCSX2 hotkey and snapshot naming are unverified for 2.9.134 (R1.2-003): T1 reads them from the ini and the developer's existing snaps rather than recall.
