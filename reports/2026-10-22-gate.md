# The gate: reference captures and a pixel tolerance

- **Date:** 2026-10-22
- **Who:** Johnny; Claude (phase 1.2 tasks)
- **Goal:** Compare the runner's boot screens against PCSX2 screenshots with a frozen pixel tolerance, so "the
  screens match" becomes a number a tool prints.
- **Outcome:** In progress (phase 1.2). T1: capture kit (settings checklist, `tools/gate/refs.py`) done.
- **Versions:** PCSX2 2.9.134 (portable, `ps2_emu/`); PS2Recomp fork at `C:\ob\up` with patches 0001-0020; SLPM-65428; Windows 11.

## Summary

T1 built the kit for taking PCSX2 reference screenshots the same way every time. The main obstacle so far: the
game's display registers, which decide how big PCSX2's screenshot will be, can't be read by the boot script, so the
screenshot size is a prediction that the first real shot has to confirm.

## Struggles

### 1. Display registers not readable from the boot script

- **Seen:** The plan's probe meant to `watch` the GS display registers (0x12000000-0x120000A0) during a hidden boot.
- **Found by:** Reading the script's memory-read callback before booting (`C:\ob\up\ps2xRuntime\src\lib\Kernel\EeScheduler.cpp:1897-1906`).
- **Cause:** The callback masks the address to RDRAM (`addr & 0x01FFFFFF`); 0x12000020 would read RDRAM 0x20, a
  wrong value with no error. No environment switch logs the registers.
- **Fix:** None by design (the plan forbids a patch for this). The probe boot was skipped; FBW is recorded as unknown,
  and the PCSX2 screenshot width (FBW*64) is predicted as 512 with 640 as the risk. The first intake dry-run checks it.
- **Evidence:** `docs/ops/gate.md` (probe section); phase-ends/current/tasks/T1.md.
- **Take-away:** Check what a debug read path can reach before spending a boot on it; a silent wrong read is worse than none.

### 2. The recompile stamp could miss what the build actually reads

- **Seen:** The plan's staleness stamp hashed C:\ob\up (HEAD + uncommitted diff), but `ob.sh recompile` builds from
  C:\ob\src, a copy that is synced from up by hand.
- **Found by:** Checking the layout before writing the coder brief (C:\ob\src is not a git repo; docs/ops/workspace.md:36).
- **Cause:** If up changes and nobody syncs src, an up-only stamp changes and the gate rebuilds the old src code. If src
  is edited directly, an up-only stamp does not change and the gate skips the rebuild.
- **Fix:** The stamp (`gate.py stamp`, 330 inputs) also hashes every hand-edited file in C:\ob\src, the tool exes, the
  ELF and overlay inputs, and only the `cmd_recompile` text of ob.sh, so gate-only edits do not force a 5-minute rebuild.
- **Evidence:** `.run/1.2/logs/ob-gate.log` (recompiled in 297 s), `ob-gate2.log` (not recompiled, wall 47.8 s).
- **Take-away:** Hash the inputs the build reads, not the repo the inputs come from.

### 3. A capture window sized on one boot missed a phase on the next

- **Seen:** With 6 captures per screen, the verify boot's main menu held one image only, while an earlier boot's 3
  captures held two (the menu text drawn one line apart on alternate fields, 2.9% of pixels, max delta 243).
- **Found by:** Checking every window of the verify boot for both field phases, not just its exit code.
- **Cause:** The main menu first runs at 15 fps (every 4th tick, always the same field) for up to 60 ticks; how long
  depends on timing before it, which a longer title window changed.
- **Fix:** Main menu window 32 captures (covers the single-phase span, then the alternation); title 64 for one full
  PRESS START pulse; the rest 6. Re-verified: both phases present.
- **Evidence:** boots t3p (120-frame probe), t3w (verify); docs/ops/gate.md "Our-side noise floor".
- **Take-away:** A window must be checked on the boot that uses it: upstream window changes move downstream timing.

### 4. PCSX2 settings changed in the UI never reached the ini

- **Seen:** `refs.py check-settings` kept reporting the same 4 mismatches; the first screenshots were window-sized
  (725x544, 799x599, then 597x448).
- **Found by:** `PCSX2.ini` mtime unchanged since PCSX2 started (02:14), with `pcsx2-qt.exe` from `ps2_emu\` running.
- **Cause:** **Unknown** whether the changes were made in a dialog that doesn't save or never made; PCSX2 rewrites its ini
  on exit, so an ini edit is only safe with it closed.
- **Fix:** With PCSX2 closed (developer's go-ahead), Claude set the 4 keys in `ps2_emu\inis\PCSX2.ini`, kept CRLF line
  endings (a `sed -i` had turned them to LF; restored), backup `PCSX2.ini.bak-20261022`. `check-settings`: `settings OK`.
- **Take-away:** check the ini, not the dialog; edit it only with PCSX2 closed.

### 5. The intake maps shots by order only

- **Seen:** the first "savedata" shot was a black 640x960 boot frame; the next was "Checking Memory Card", not the YES/NO
  prompt; later one boot with shots of 12 different screens was mapped as two boots of six (charselect-a was the title).
- **Found by:** Claude opening each shot / a contact sheet before the real intake, not trusting the dry-run labels.
- **Cause:** `refs.py intake` labels the n-th shot after `begin` by position; any extra or early shot shifts every label.
- **Fix:** re-`begin` and reshoot; extra shots moved out of `ps2_emu\snaps`. Final set: 12/12 at 512x448, every picture
  checked against its label (03:00-03:04), intake wrote `C:\ob\ref` and `gate/ref_manifest.json`.
- **Take-away:** look at the pictures before the intake; a label check by size alone passes wrong screens.

### 6. PCSX2 does not agree with itself on animated screens, and does not show fields the way we do

- **Seen:** PCSX2 ref a vs ref b is byte-identical on savedata, access and capcom, but differs on 14-44% of pixels
  (delta > 8) on title, mainmenu and charselect; a shifted glyph changes only 0.08-0.15%. Separately, every PCSX2 ref
  has 448 distinct lines while every runner frame repeats each even line on the next.
- **Found by:** T5 scratch scripts (`.run/1.2/t5_tol.py`, `t5_field.py`) and an a|b|diff contact sheet.
- **Cause:** the three screens have animated backgrounds (fog, scrolling eye, moving layer), so two shots are two
  animation moments. The runner's `applyFieldPresentation` (gs_cpu_backend.cpp:397-410) bob-doubles one field;
  PCSX2 with deinterlace Off shows the whole frame.
- **Fix:** none yet. No p can separate either effect from damage; T5 returns `question` with options in
  `gate/TOLERANCE.md` (frame-locked references for Q1; field presentation as a runner fault for Q2).
- **Take-away:** check that the reference agrees with itself before fitting any tolerance; animation is not noise.

### 7. Splitting animated screens into UI and background did not give clean UI regions

- **Seen:** on title, mainmenu and charselect no UI rectangle is the same in PCSX2 shot a and shot b: the quietest
  (copyright line, a corner) still differ on ~140 px, the logo/menu/portraits on 900-35000 px; the strict limit is ~23 px.
- **Found by:** T5 block map and per-rectangle measurement (`.run/1.2/t5_blocks.py`, `t5_regions.py`).
- **Cause:** the UI is translucent over, or crossed by, the animated layer (a scanline band runs through the main-menu
  logo; PRESS START pulses). The coarse background check works (black background 3-35x above noise) but cannot see
  a missing UI layer (menu removed: 0.87 vs noise 3.31).
- **Fix:** none; no coder briefed. Back to the developer with options (frame-locked references first).
- **Take-away:** measure a region's self-agreement before building a region metric on it.
- **Outcome:** developer chose full-frame d/p with a best-frame window covering the animation (UNVERIFIED until
  the backgrounds render; background-only fallback).

### 8. The animated backgrounds are movies, so their loop cannot be measured yet

- **Seen:** our title/mainmenu/charselect frames show no background motion over 120 frames; the decomp has no
  animation counters for them, only movie start calls.
- **Found by:** T5 frame series (`.run/1.2/t5_anim.py`), a code retriever (R1.2-008), a scan of the ISO's NETBIO
  archives for Sofdec streams (`t5_sfd2.py`: ~200 streams, 3.55-377 s).
- **Cause:** the backgrounds are CRI Sofdec movies (PS2title1/2_eng.sfd, PS2select.sfd); movies are M5 and not
  started, so the runner draws black. Which stream is which could not be resolved (no sector table found).
- **Fix:** none; capture windows left unchanged; back to the developer (re-check timing and window size).
- **Take-away:** before planning around "when X renders", find out what X is made of.
- **Outcome:** developer chose to gate only the static screens in generation 1; title, main menu and character
  select are advisory (printed, not in the exit code) until movie playback exists; GENERATION_PLAN reworded.
