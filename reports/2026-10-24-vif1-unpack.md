# VIF1 UNPACK (patch 0053) and the DMA chain copy

- **Date:** 2026-10-24
- **Who:** the developer, one Claude Code session
- **Goal:** cut `processVIF1Data` (22% of the J's Bar game thread) and parse DMA chains in place.
- **Outcome:** PS2Recomp 0053 (`C:\ob\up` `330abdc`): the UNPACK loop, bit-identical (recorded-hash test). Busy
  stretch: `processVIF1Data` 22.3% -> 6.8%, game thread 41.5 -> 33.8 CPU-s per 45 s, no longer saturated. `ob.sh check`
  53 s -> 47-48 s, same ticks; gate 3/3. Chains in place: **not done** (2.7% left, high risk; below).
- **Versions:** PS2Recomp `C:\ob\up` 0052 + 0053; Windows 11, MSVC 19.44.

## Summary

hostprof gained `--lines FUNC` (PDB line numbers of the samples in a function). In `processVIF1Data` 59% of samples sat on
the per-field mask/mode loop of UNPACK and 19% on its store to VU1 memory: the loop re-read `vif1_regs` for every field of
every vector (stores through the VU1 data pointer may alias them, so the compiler reloads) and divided by WL twice per
vector. Locals, counters and an unmasked fast path removed most of it with no change in results: a recorded-hash test over
random VIF1 streams, made with the old code before the change, passes unchanged.

## Struggles

### 1. Proving "same results" for a rewrite of the hottest loop

- **Approach:** a deterministic generator of VIF1 segments covering every UNPACK form and setting; the hash of VU1 data
  + ROW/COL after each of 8 segments recorded with the **old** interpreter (`ps2_memory_tests.cpp`), then the rewrite.
- **Evidence:** 8/8 hashes equal after the rewrite; with the final ROW write-back removed (a mutation, `C:\ob\src`
  only, restored and `cmp`-checked) ps2x drops to 530/532.
- **Take-away:** record outputs of the old code before replacing it; a generated stream is cheap.

### 2. "Parse DMA chains in place" not done

- **Why:** a VIF chain in memory is not one stream: each 16-byte DMA tag's lower 8 bytes are the DMA header and only its
  upper 8 (two VIFcodes, CHCR.TTE) belong to the VIF stream, between the tags' data blocks. Parsing in place needs a VIF1
  parser that can stop and resume inside any command (UNPACK, STROW/STCOL, MPG; today only DIRECT can). After 0052's
  buffer recycling the copy is ~2.7% of the game thread (`memchr` 2.3% plus part of `memmove`, all from
  `_Insert_counted_range` in `writeIORegister`, `hostprof-vif-after.txt`), and the thread now has headroom.
- **Decision:** not worth the risk now. Revisit only if the game thread is saturated again.
