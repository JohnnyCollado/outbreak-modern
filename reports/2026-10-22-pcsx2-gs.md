# Phase 1.3: PCSX2 GS renderer

- **Date:** 2026-10-22
- **Who:** Johnny; PA3 phase 1.3 experts and coders
- **Goal:** Run PCSX2 2.9.134's GS in-process in the PS2Recomp runner (SW for verification, Vulkan for presentation), selectable with `PS2X_GS`, the CPU GS kept as an unfixed fallback. Replaces the superseded plan "boot logos match PCSX2" (CPU GS fault fixes), stopped on 2026-10-22 (docs/ops/gs.md).
- **Outcome:** In progress. T7 done: `ob_pcsx2_gs` static lib builds and its smoke passes (SW snapshot colours exact, VK GSopen ok).
- **Versions:** PS2Recomp eb8688b+0001-0020; PCSX2 v2.9.134 (a81f1aa); Windows 11, MSVC 19.44, CMake 3.30.

## Summary

T7 built PCSX2's GS alone as a static library without editing PCSX2: deps cut to zstd + shaderc, PCSX2's own
source lists read at configure time, D3D headers shimmed, 96 missing host symbols stubbed. It linked after four
link rounds and passed first run. The one trap: the Vulkan SDK on PATH supplied its own shaderc DLL and hid a
missing staged DLL; the build script now strips the SDK from PATH, proven by a negative control.

## Struggles

### 1. PCSX2's dependency script cannot run as-is

- **Seen:** `build-dependencies.bat` builds Qt, FFmpeg, SDL and others, downloading from qt.io, ffmpeg.org, sourceforge, nuget, googleapis; it also expects 7-Zip at `C:\Program Files\7-Zip`, which is not installed.
- **Found by:** reading the script's `downloadfile` lines (83-137) and its `SEVENZIP` line (26).
- **Cause:** the script serves the whole Qt frontend; the GS link needs only zstd (GSLzma/GSDump) and shaderc (Vulkan shader compiler, loaded as a DLL).
- **Fix:** `tools/ob/pcsx2-deps.bat` copies the script's zstd and shaderc sections verbatim (same github.com URLs, SHA-256 pins, `shaderc-changes.patch`, cmake lines), unzipping with Windows' own `tar.exe` instead of 7-Zip. PNG/JPEG/WebP/ryml users (`common/Image.cpp`, `YAML.cpp`, `GS/GSPng.cpp`) are stubbed, not built.
- **Evidence:** tools/ob/pcsx2-deps.bat; T7 log.
- **Take-away:** build only what the link needs; every download stays checksum-pinned by upstream's own script.

### 2. Windows paths lost their backslashes on the way to cmd

- **Seen:** the deps bat failed with "Access is denied" and "The system cannot find the path specified".
- **Found by:** an argument-echo bat: `%~1` arrived as `C:obpcsx2`.
- **Cause:** unquoted `C:\ob\pcsx2` in bash: the backslashes are escapes.
- **Fix:** single-quote Windows paths passed to `cmd /c`.
- **Evidence:** .run/1.3/logs/pcsx2-deps.log (first two runs).
- **Take-away:** in Git Bash, quote every Windows path given to cmd, or build it with `cygpath -w`.

### 3. Source-list extraction stopped at the first ')'

- **Seen:** the first build (b1) got wrong source lists from `ob_extract`.
- **Found by:** the first build's failures (T7.c1 log, iteration b1).
- **Cause:** the search for the list's closing `)` included the anchor itself, so a `)` inside the anchor text ended the list.
- **Fix:** `ob_extract` searches for the closing paren after the anchor; FATAL_ERROR when an anchor is missing, so an upstream rename fails loudly.
- **Evidence:** native/pcsx2_gs/CMakeLists.txt (`ob_extract`); T7.c1 log, iteration b1.
- **Take-away:** read upstream's lists, never hand-copy them, and make the reader fail on a missing anchor.

### 4. GS.cpp needs DirectX-Headers even with DX11/DX12 off

- **Seen:** compile error `directx/d3d12.h` not found.
- **Found by:** the include chain: `GS.cpp`/`GSUtil.cpp` include `DX11/D3D.h`, `GSDevice11.h`, `DX12/GSDevice12.h` unconditionally on `_WIN32`.
- **Cause:** PCSX2 always builds D3D on Windows; there is no switch.
- **Fix:** shim headers in `native/pcsx2_gs/include/GS/Renderers/DX11|DX12/`, searched before the PCSX2 tree: three `D3D::` declarations (stubbed, `GetPreferredRenderer` = VK) and `using GSDevice1x = GSDeviceVK;` for dead branches. No PCSX2 edit, no patch.
- **Evidence:** native/pcsx2_gs/include/GS/; T7.c1 log.
- **Take-away:** an include-path shim beats a patch when the code behind it is dead.

### 5. 96 unresolved symbols at first link

- **Seen:** first link: 96 unresolved externals (Host, VMManager, MTGS, EmuConfig/GSOptions, PerformanceMetrics, capture, dumps, texture replacements, ImGuiManager, ...).
- **Found by:** the linker's list, round by round (96, 7, 3, 0).
- **Cause:** the GS reaches into core, UI and config; `Pcsx2Config.cpp` would pull CDVD/memcard/Pad/USB/audio.
- **Fix:** four stub files (`native/pcsx2_gs/stubs/`); GSOptions members copied verbatim from `Pcsx2Config.cpp` with line cites; `ImGuiManager::Initialize` makes a real empty context because `GSDeviceVK::RenderImGui` runs every present. 0 core files beyond GS/common.
- **Evidence:** native/pcsx2_gs/stubs/*.cpp; T7.c1 log, iterations l1-l4.
- **Take-away:** stubbing to the linker's list keeps the GS-only link small; the copied config code must be re-copied on a PCSX2 bump.

### 6. The Vulkan SDK's shaderc DLL hid a missing staged DLL

- **Seen:** with the staged `shaderc_shared.dll` removed, the smoke still passed.
- **Found by:** a negative control run by the coder.
- **Cause:** `C:\VulkanSDK\1.4.341.1\Bin` is on PATH and ships its own `shaderc_shared.dll`; Windows found it there.
- **Fix:** `cmd_pcsx2_gs` (tools/ob.sh) runs the smoke with every `vulkansdk` PATH entry removed. Control: DLL removed + SDK off PATH = "Failed to compile utility pipelines", SW and VK GSopen failed, exit 1; DLL restored = PASS.
- **Evidence:** tools/ob.sh `cmd_pcsx2_gs`; T7.c1 log Notes.
- **Take-away:** a dev machine's SDK on PATH can satisfy a DLL your shipped build lacks; test with it off PATH.
