# Phase 1.3: PCSX2 GS renderer

- **Date:** 2026-10-22
- **Who:** Johnny; PA3 phase 1.3 experts and coders
- **Goal:** Run PCSX2 2.9.134's GS in-process in the PS2Recomp runner (SW for verification, Vulkan for presentation), selectable with `PS2X_GS`, the CPU GS kept as an unfixed fallback. Replaces the superseded plan "boot logos match PCSX2" (CPU GS fault fixes), stopped on 2026-10-22 (docs/ops/gs.md).
- **Outcome:** T7 done: `ob_pcsx2_gs` static lib builds, smoke passes. T8 done: `PS2X_GS=pcsx2-sw` boots all 37 gate steps with PCSX2's SW GS drawing; gated shares savedata 0.042241, access 0.247284, capcom 0.080510 (CPU baseline 0.043597, 0.248753, 0.082450); still 0/3 green: the remaining faults are shared with the CPU GS.
- **Versions:** PS2Recomp eb8688b+0001-0023; PCSX2 v2.9.134 (a81f1aa); Windows 11, MSVC 19.44, CMake 3.30.

## Summary

T7 built PCSX2's GS alone as a static library without editing PCSX2: deps cut to zstd + shaderc, PCSX2's own
source lists read at configure time, D3D headers shimmed, 96 missing host symbols stubbed. It linked after four
link rounds and passed first run. The one trap: the Vulkan SDK on PATH supplied its own shaderc DLL and hid a
missing staged DLL; the build script now strips the SDK from PATH, proven by a negative control.

T8 put that GS behind a hook in the runner (PS2Recomp patches 0021-0023 plus the adapter in native/pcsx2_gs).
Four faults stood between the first boot and real pictures: a crash from feeding PCSX2 split GIF units, a "stall"
that was really every frame being rejected by a row-stride check, black frames from register writes that never
reached PCSX2 and from stream framing the runtime invents for its own GS, and a crash that went away with the
framing fixes. The SW GS now boots the whole gate script and scores slightly better than the CPU GS on all three
gated screens; what remains wrong is shared by both GSes.

## Struggles

### 1. PCSX2's dependency script cannot run as-is

- **Seen:** `build-dependencies.bat` builds Qt, FFmpeg, SDL and others, downloading from qt.io, ffmpeg.org, sourceforge, nuget, googleapis; it also expects 7-Zip at `C:\Program Files\7-Zip`, which is not installed.
- **Found by:** reading the script's `downloadfile` lines (83-137) and its `SEVENZIP` line (26).
- **Cause:** the script serves the whole Qt frontend; the GS link needs only zstd (GSLzma/GSDump) and shaderc (Vulkan shader compiler, loaded as a DLL).
- **Fix:** `tools/ob/pcsx2-deps.bat` copies the script's zstd and shaderc sections verbatim (same github.com URLs, SHA-256 pins, `shaderc-changes.patch`, cmake lines), unzipping with Windows' own `tar.exe` instead of 7-Zip. PNG/JPEG/WebP/ryml users (`common/Image.cpp`, `YAML.cpp`, `GS/GSPng.cpp`) are stubbed, not built.
- **Evidence:** tools/ob/pcsx2-deps.bat; T7 log.
- **Take-away:** build only what the link needs; every download stays checksum-pinned by upstream's own script.

### 2. Windows paths lost their backslashes on the way to cmd

- **Seen:** the deps bat failed with "Access is denied" and "The system cannot find the path specified".
- **Found by:** an argument-echo bat: `%~1` arrived as `C:obpcsx2`.
- **Cause:** unquoted `C:\ob\pcsx2` in bash: the backslashes are escapes.
- **Fix:** single-quote Windows paths passed to `cmd /c`.
- **Evidence:** .run/1.3/logs/pcsx2-deps.log (first two runs).
- **Take-away:** in Git Bash, quote every Windows path given to cmd, or build it with `cygpath -w`.

### 3. Source-list extraction stopped at the first ')'

- **Seen:** the first build (b1) got wrong source lists from `ob_extract`.
- **Found by:** the first build's failures (T7.c1 log, iteration b1).
- **Cause:** the search for the list's closing `)` included the anchor itself, so a `)` inside the anchor text ended the list.
- **Fix:** `ob_extract` searches for the closing paren after the anchor; FATAL_ERROR when an anchor is missing, so an upstream rename fails loudly.
- **Evidence:** native/pcsx2_gs/CMakeLists.txt (`ob_extract`); T7.c1 log, iteration b1.
- **Take-away:** read upstream's lists, never hand-copy them, and make the reader fail on a missing anchor.

### 4. GS.cpp needs DirectX-Headers even with DX11/DX12 off

- **Seen:** compile error `directx/d3d12.h` not found.
- **Found by:** the include chain: `GS.cpp`/`GSUtil.cpp` include `DX11/D3D.h`, `GSDevice11.h`, `DX12/GSDevice12.h` unconditionally on `_WIN32`.
- **Cause:** PCSX2 always builds D3D on Windows; there is no switch.
- **Fix:** shim headers in `native/pcsx2_gs/include/GS/Renderers/DX11|DX12/`, searched before the PCSX2 tree: three `D3D::` declarations (stubbed, `GetPreferredRenderer` = VK) and `using GSDevice1x = GSDeviceVK;` for dead branches. No PCSX2 edit, no patch.
- **Evidence:** native/pcsx2_gs/include/GS/; T7.c1 log.
- **Take-away:** an include-path shim beats a patch when the code behind it is dead.

### 5. 96 unresolved symbols at first link

- **Seen:** first link: 96 unresolved externals (Host, VMManager, MTGS, EmuConfig/GSOptions, PerformanceMetrics, capture, dumps, texture replacements, ImGuiManager, ...).
- **Found by:** the linker's list, round by round (96, 7, 3, 0).
- **Cause:** the GS reaches into core, UI and config; `Pcsx2Config.cpp` would pull CDVD/memcard/Pad/USB/audio.
- **Fix:** four stub files (`native/pcsx2_gs/stubs/`); GSOptions members copied verbatim from `Pcsx2Config.cpp` with line cites; `ImGuiManager::Initialize` makes a real empty context because `GSDeviceVK::RenderImGui` runs every present. 0 core files beyond GS/common.
- **Evidence:** native/pcsx2_gs/stubs/*.cpp; T7.c1 log, iterations l1-l4.
- **Take-away:** stubbing to the linker's list keeps the GS-only link small; the copied config code must be re-copied on a PCSX2 bump.

### 6. The Vulkan SDK's shaderc DLL hid a missing staged DLL

- **Seen:** with the staged `shaderc_shared.dll` removed, the smoke still passed.
- **Found by:** a negative control run by the coder.
- **Cause:** `C:\VulkanSDK\1.4.341.1\Bin` is on PATH and ships its own `shaderc_shared.dll`; Windows found it there.
- **Fix:** `cmd_pcsx2_gs` (tools/ob.sh) runs the smoke with every `vulkansdk` PATH entry removed. Control: DLL removed + SDK off PATH = "Failed to compile utility pipelines", SW and VK GSopen failed, exit 1; DLL restored = PASS.
- **Evidence:** tools/ob.sh `cmd_pcsx2_gs`; T7.c1 log Notes.
- **Take-away:** a dev machine's SDK on PATH can satisfy a DLL your shipped build lacks; test with it off PATH.

### 7. T8: access violation in PCSX2 on the first real boot (PACKED overread)

- **Seen:** first `PS2X_GS=pcsx2-sw` gate: boot AV 0xC0000005.
- **Found by:** a temporary unhandled-exception filter + StackWalk64 in the adapter: `GSState::GIFRegHandlerPRIM` <- `GSState::Transfer<3>` (GSState.cpp:3457) <- `ob_gs_gif` <- `GifArbiter::drain`; the read was past the packet.
- **Cause:** our arbiter hands DMA slices that can split a GIFtag from its data. `Transfer`'s PACKED loop runs a register handler before it checks the remaining size, so a call ending right after a tag with NLOOP > 0 underflows the size and reads past the buffer. PCSX2's own Gif_Unit only ever hands whole units.
- **Fix:** the adapter keeps a per-path tail and passes only whole GIFtag units (T8.c2, 1d2d588).
- **Evidence:** logs/T8.c2.md; native/pcsx2_gs/adapter/pcsx2_side.cpp `WholeUnitsQwc`.
- **Take-away:** feed an emulator's GS the unit granularity its own front end guarantees, not whatever the transport slices.

### 8. T8: the boot "stalled" at the save-data screen (latch stride)

- **Seen:** the pcsx2-sw gate timed out at step 3 (`capture savedata 6`), 0 frames dumped; VBlank kept running.
- **Found by:** a no-op control (adapter that never calls PCSX2, snapshot null) stalled identically, so the fault was on the runtime side; then counters around UploadFrame/latch: snapshots were 512x448 every vsync, yet "no latched frame" almost every time.
- **Cause:** patch 0021 latched the external 512-wide packed frame as-is; the host presentation copy reads a 640-pixel row stride and its bounds check rejected every frame, so no capture could complete. Not a stall at all (c2's control had no snapshot either, so it could never finish).
- **Fix:** patch 0022 copies packed external rows into the 640 stride (T8.c3, 81bc8f8), with a test.
- **Evidence:** logs/T8.c3.md "Diagnosis".
- **Take-away:** check what the script step waits for before calling a boot stalled; a no-op control must still satisfy the step's own completion condition.

### 9. T8: frames all black (three causes)

- **Seen:** after 0022 the boot ran to the title, but every sw frame was solid black.
- **Found by:** reading the HLE libgraph stubs (sceGsPutDrawEnv, sceGsSwapDBuff, clear packets), then per-vsync diagnostics in the adapter (path packet counts, carry sizes, non-zero pixels at DISPFB).
- **Cause 1:** the HLE stubs write draw-environment registers straight into the CPU GS through `GS::writeRegister`; PCSX2 never saw FRAME/ZBUF/XYOFFSET/SCISSOR/TEST.
- **Cause 2:** the VIF1 interpreter resubmits the rest of a cut PATH2 IMAGE behind a synthesized IMAGE tag (ps2_vif1_interpreter.cpp:307-323). The CPU GS needs it; PCSX2 still had the original IMAGE open, so the extra qword shifted the stream (31,725 such tags in one boot).
- **Cause 3:** the per-path carry kept any cut unit; one untagged 135,280-byte PATH2 DIRECT decoded as a huge REGLIST and swallowed every later PATH2 packet (carry stuck at 1-3.4 MB).
- **Fix:** patch 0023 tees each `writeRegister` as a 32-byte PACKED A+D packet (test fails on 0022 alone); the adapter drops the synthetic tag when it continues an open IMAGE, and carries only an open IMAGE unit (T8.c4, 846ea83).
- **Evidence:** logs/T8.c4.md; .run/1.3/logs/ob-gate-sw-diag*.log.
- **Take-away:** an HLE layer that writes the GS directly bypasses the GIF stream; every such side door must be teed to an external GS. Runtime-synthesized stream data is a private contract between producer and its own consumer.

### 10. T8: PSMT4 WriteImage access violation at the title -> main menu transition

- **Seen:** AV (read) in `GSLocalMemoryFunctions::WriteImage<20,...>` <- `FlushWrite` <- `ApplyTEX0` <- `Transfer<3>` on the EE thread at step 22.
- **Found by:** temporary VEH + dbghelp stack (T8.c3); a control without the PATH3 tee crashed the same way.
- **Cause:** most likely the stuck PATH2 carry of struggle 9 (an IMAGE transfer left pending with stale TRXREG); not separately instrumented.
- **Fix:** none specific; after the two adapter carry fixes it did not recur over two full boots.
- **Evidence:** logs/T8.c3.md "The wall"; logs/T8.c4.md.
- **Take-away:** fix stream framing before chasing a crash deep inside the consumer.

### 11. T8: a diagnostic read changed the result

- **Seen:** with a readback of DISPFB via `GSReadLocalMemoryUnsync` added for diagnostics, the run broke after vsync 6.
- **Cause:** it drives PCSX2's local-to-host transfer state machine (GSState.cpp:3304-3333).
- **Fix:** read `g_gs_renderer->m_mem` directly; the snapshot does the same.
- **Take-away:** a probe must not share state with the thing probed.

## T12: save-data letters lose strokes (2026-10-22)

- **Seen:** on the save-data screen the letters are thin and broken; the same under the CPU GS and PCSX2 (SW and
  Vulkan), so not a renderer fault. The developer's visible-window screenshot showed it too.
- **Found by:** decoding the font straight from the disc (`netbio00.dat`, AFS at 0x800, entries 554 `d20go04.bin` /
  555 `s20le04.bin`: 20x20 glyphs, 2 bpp, 100 bytes each) as ground truth; logging every GIF packet the GS received
  (`C:\ob\t12\gif.bin`, 44,664 PSMT4 uploads to VRAM 0x2a00) and dumping PCSX2's VRAM (`C:\ob\t12\vram-178.bin`).
- **Cause:** PS2Recomp's VIF1 reader (`ps2_vif1_interpreter.cpp:307-333`). The game uploads each glyph as
  `DIRECT[... IMAGE tag]`, then `NOP, DIRECTHL 13, <glyph>`. Real hardware (and PCSX2, `Vif_Codes.cpp
  _vifCode_Direct`) starts the image data right after the DIRECTHL word. Our reader forwarded the NOP and DIRECTHL
  words as image data, so every glyph arrived shifted 16 bytes with its last qword dropped; the CLUT at 0x2a02 got
  the same treatment (the VRAM dump held the VIFcode `0x51000004` where colours belong).
- **Fix:** patch 0025, `PS2Memory::feedVif1DirectPayload`: an open IMAGE continues in the next DIRECT/DIRECTHL
  payload (unaligned, right after the VIFcode); raw continuation only for a DIRECT truncated at a buffer end. Three
  tests fail without it (ps2x_tests 474/477 on the old reader; 477/477 with it).
- **Evidence:** pcsx2-vk gate savedata 0.042241 -> 0.003353, access 0.247877 -> 0.000000 (GREEN), capcom
  0.081552 -> 0.001251; cpu gate savedata 0.043597 -> 0.042668, access 0.248753 -> 0.050319, capcom
  0.082450 -> 0.018507 (`.run/logs/t12-gate-*.log`). Frames viewed against `C:\ob\ref\*-a.png`: clean glyphs,
  ACCESS in navy/black, CAPCOM no longer shifted or clipped. This was also T8's "untagged 135,280-byte PATH2
  DIRECT".
- **Take-away:** when two independent renderers show the same fault, check the bytes they are fed, not the
  renderers; decode the asset from the disc first so there is a ground truth to compare against. Diagnostic
  reads of PCSX2 VRAM must use `m_mem` directly (`GSReadLocalMemoryUnsync` mutates transfer state).

## Patch 0028: a routine runtime change rebuilt the whole game (2026-10-22)

### 1. Every runtime fix cost a 5-7 minute game rebuild

- **Seen:** patches 0026/0027 (GS frontend, scheduler fields) rebuilt all 180 unity units of generated game code:
  327 s wall, 3,778 s CPU (`C:\ob\r\.ninja_log`).
- **Cause:** every generated source included `ps2_runtime.h`, the runtime's whole interior; the generated code
  only calls ~20 entry points.
- **Fix:** patch 0028, `ps2_runtime_api.h` (game-facing header) + emitters writing `ps2x_*(runtime, ...)`.
- **Evidence:** after a touch of `ps2_runtime.h` + `gs_frontend.h`: 40 runtime build steps, 0 game units, runner
  build 28 s (`C:\ob\logs\ob-runner-build.log`). One-time full rebuild 361 s. Tests 490/490; 476/490 with the old
  emitters. Gates unchanged: pcsx2-vk savedata 0.003353, access 0.000000 GREEN, capcom 0.001251; cpu 0.042668,
  0.050319, 0.018507 (`.run/logs/t28-gate-*.log`).
- **Take-away:** generated code should depend on a narrow, stable header; anything it includes is a rebuild trigger
  for thousands of files.

### 2. The 0028 helper was stopped mid-edit

- **Seen:** the helper's work sat uncommitted in `C:\ob\up` (19 files + 3 new); the test referenced a support file
  that did not exist and was not registered in the test build.
- **Fix:** reviewed the diff, wrote `ps2_runtime_api_support.cpp`, registered the tests, added the include-walk test
  the header's comment promised and an emitter include test.
- **Take-away:** read the whole half-done diff before building on it; a header comment can promise a test that
  was never written.

### 3. `ob.sh test` passed a stale binary

- **Seen:** the first 0028 test build failed to compile, yet `ob.sh test` exited 0 and reported 479/479: the
  pre-0028 `ps2x_tests.exe` ran.
- **Cause:** the build error only printed a line; it did not set the red flag.
- **Fix:** `tools/ob.sh` `cmd_test`: a build error sets red and says the counts are from a stale binary.
- **Take-away:** a test runner must fail when the thing it runs could not be rebuilt.

### 4. A macro without parentheses

- **Seen:** `GPR_U32(&r.ctx, 2)` failed to compile (C2819) in the new API test.
- **Cause:** `GPR_U32` expands `ctx_ptr->r[...]` without parenthesising the argument, so `&r.ctx->r` parses as
  `&(r.ctx->r)`.
- **Fix:** the test passes a named pointer, as generated code does; the macro is upstream's and left alone.

### 5. Timed boots: CPU GS vs PCSX2 Vulkan (patch 0027 log, after 0028)

Hidden `gate/boot.script` boots, `PS2X_FRAME_TIME=C:\ob\logs\ft-<gs>-<n>.csv`, budget 16.68 ms (59.94 Hz):

|---|---|---|---|---|---|---|---|---|
| cpu-1 | 3101 | 77.1 | 14.53 | 14.45 | 91.03 | 138.37 | 496.1 | 44.8% |
| cpu-2 | 3049 | 52.1 | 15.58 | 15.57 | 48.86 | 101.00 | 396.0 | 40.4% |

### 6. Frame-time "busy" equalled "wall"; the one ~1 s Vulkan frame

- **Seen:** in all four timed boots busy == wall (item 5), so the 0027 log could not show a frame's cost.
- **Cause:** when every guest thread is blocked (the normal state while the game waits for the next vsync),
  `EeScheduler::run` sleeps in `waitForEvent()` (`EeScheduler.cpp:201`, wait at :2115). Patch 0027 only counts the
  sleep in `processDueDeadlines` (:1829), which is rarely reached.
- **Found by:** reading both wait sites; then a throwaway build of `C:\ob\src` that also counted the :2115 wait
  (not committed, `C:\ob\src` restored and rebuilt).
- **Evidence:** with the idle wait counted (`C:\ob\logs\ftx-*.csv`): pcsx2-vk busy median 4.72 ms, p95 13.53,
  3.3% of frames over budget; cpu busy median 9.42 ms, p95 39.58, 32.3% over budget (was 16.6 ms and ~45% for both).
  The experiment's runtime-only edit rebuilt the runner in 8 s (patch 0028 at work).
- **The ~1 s Vulkan frame:** one frame per boot, tick 2 only. `EnsureOpen` (`native/pcsx2_gs/adapter/pcsx2_side.cpp:93`)
  opens PCSX2's GS on first use with `DisableShaderCache = true` (:88); `C:\ob\logs\pcsx2-gs.log` shows the device
  ready at 1.05 s and shaders done at 1.88 s. Start-up cost, not a stall. The hidden boot presents with
  `VK_PRESENT_MODE_IMMEDIATE_KHR` (vsync off), so no present wait is involved.
- **Fix:** proposed as patch 0029 (count the `waitForEvent` waits); not made yet.
- **Take-away:** a "time spent waiting" counter must cover every place the thread sleeps; check with a run where the
  answer is known before reading the numbers.

- **Evidence:** new test fails without it (busy 30497 us of wall 30497 us, 490/491), passes with it (491/491; iop
  4/4, gs_cache 45/45). Runner rebuild 10 s. Gates unchanged (pcsx2-vk 0.003353 / 0.000000 GREEN / 0.001251; cpu
  0.042668 / 0.050319 / 0.018507, `.run/logs/t29-gate-*.log`). Timed boots (`C:\ob\logs\ft29-*.csv`):

| Run | vsyncs | total s | busy med ms | busy p95 | busy p99 | busy > budget |

| pcsx2-vk | 2711 | 45.2 | 4.89 | 14.42 | 33.86 | 3.4% |
| cpu | 2740 | 47.1 | 9.77 | 41.88 | 49.30 | 35.2% |
