# An SDK on PATH can supply a DLL your build forgot to stage

Problem: a test exe that loads a DLL at runtime (e.g. PCSX2's GS loads `shaderc_shared.dll`) passes on a dev
machine even when the DLL was never staged beside it, because an installed SDK's `Bin` dir is on PATH and ships the
same-named DLL (here `C:\VulkanSDK\1.4.341.1\Bin\shaderc_shared.dll`). The test then proves nothing about the
shipped layout, and may load a different version than the one you pinned.

Technique:
- Run the test with the SDK stripped from PATH, in a subshell so nothing else changes (Git Bash):
  `np=$(printf '%s' "$PATH" | tr ':' '\n' | grep -v -i vulkansdk | paste -sd:); ( cd "$b" && PATH="$np" ./test.exe )`
- Prove it with a negative control once: remove the staged DLL, run with the SDK off PATH, expect failure
  (here "Failed to compile utility pipelines", exit 1); restore it, expect pass.
- Shipped runners stage the DLL beside the exe; never rely on PATH.

Where: `tools/ob.sh` `cmd_pcsx2_gs`; docs/ops/gs.md Gotchas.
